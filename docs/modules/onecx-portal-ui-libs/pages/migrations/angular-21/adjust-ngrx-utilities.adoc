[#adjust-ngrx-utilities]
= Adjust ngrx utilities usage

In OneCX v8, some `@onecx/ngrx-accelerator` utility names changed.
If your app still uses the old utility names, TypeScript compilation fails after upgrade.

[NOTE]
====
This adaptation is required only if you changed generated code, added custom ngrx implementation, or if your project is affected by these renamed utilities as a breaking change.
====

== Required rename

* `filterForQueryParamsChanged` -> `filterOutQueryParamsHaveNotChanged`
* `filterForOnlyQueryParamsChanged` -> `filterOutOnlyQueryParamsChanged`

== Example

.Before
[source,typescript]
----
import {
  filterForQueryParamsChanged,
  filterForOnlyQueryParamsChanged,
} from '@onecx/ngrx-accelerator'
----

.After
[source,typescript]
----
import {
  filterOutQueryParamsHaveNotChanged,
  filterOutOnlyQueryParamsChanged,
} from '@onecx/ngrx-accelerator'
----

== Fragment instead of query params

The ngrx-accelerator also provides fragment-based variants of the query params utilities.
The fragment format is `#<path>?a=b&c=d` (for example `#search?name=x`): the part before `?` is a prefix, the part after `?` holds the criteria.
If you want to keep the search criteria in the URL fragment instead of the query params, use these utilities:

[cols="2",options="header"]
|===
| Old (query params) | New (fragment)

| `filterOutQueryParamsHaveNotChanged` | `filterOutFragmentParamsHaveNotChanged`
| `filterOutOnlyQueryParamsChanged` | `filterOutOnlyFragmentParamsChanged`
| `createQueryParamsEffect` | `createFragmentParamsEffect`
|===
