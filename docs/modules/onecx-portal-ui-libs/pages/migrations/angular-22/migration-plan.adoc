= Migrate OneCX App from Angular 21 to Angular 22

:idprefix:
:idseparator: -

[#overview]
== Overview

[IMPORTANT]
====
 This guide is a work in progress. Angular 22 support and OneCX UI libraries v9.0.0 are not final yet. Angular 22 support is delivered with an updated OneCX Shell (the Angular 22 preloader) and the UI libraries v9.0.0. The detailed, step-by-step migration guide is being published here as it is finalized.
====

This guide explains the changes an application needs to be aware of when moving to **Angular 22** and the accompanying OneCX UI libraries **v9.0.0**.

The one change that applies to every application is that the `@onecx/*` UI libraries change the component library they are built on: from **PrimeNG** to **Optimus UI**. Optimus UI is an open-source, community-maintained fork of PrimeNG that keeps the PrimeNG API. Because PrimeNG has stopped being open source, moving to Optimus UI lets OneCX keep its own libraries fully open source while staying close to the PrimeNG APIs that most applications already use.

For the high-level plan and timing across the UI libraries and Shell, see the xref:onecx-docs-overview:release-overview.adoc[Release Overview].

[#why-were-changing]
== Why we're changing

PrimeNG, the component library OneCX's UI libraries have been built on, stopped being open source. To keep OneCX's own libraries fully open source, we are moving them onto **Optimus UI** — an open-source fork of PrimeNG that preserves the PrimeNG API. This is the minimal, most compatible change available: the same components, the same PrimeNG-style selectors and inputs, maintained as open source.

[#what-changes]
== What changes for you

The migration is a single **hard cutover**: the `@onecx/*` libraries move to Optimus UI in the v9.0.0 release. There is no parallel old/new support window — you migrate on your own schedule, guided by this guide and the step-by-step guide that will be published alongside it.

The changes fall into a few groups:

* **Library and toolchain versions.** Update the OneCX UI libraries to **v9.0.0** and the toolchain Angular 22 requires (Nx, TypeScript, and Node). The step-by-step guide lists the exact versions to check.
* **A few public names change.** To reflect the new dependency honestly, a small number of public entry points are renamed. The most visible are the theme entry point (the PrimeNG entry point is renamed to its Optimus counterpart) and the PrimeNG wrapper module, which is renamed in place. These are listed as breaking changes in the v9.0.0 release notes.
* **A component API change.** One confirmed API change affects the dialog component: its `header` input is now a signal. The step-by-step guide covers how to adjust this.
* **Change detection is now explicit.** The official Angular migration makes components opt into `ChangeDetectionStrategy.OnPush` explicitly where they previously had none. Behavior is unchanged; the intent is simply to make it explicit.

[#compatibility]
== Compatibility

OneCX libraries remain **library-agnostic at the application level** throughout. Consuming applications are not forced onto any particular UI library:

* If your application uses PrimeNG-style components (for example via Optimus UI), that API is preserved and continues to work.
* You are also free to use another Angular-compatible component library.

There is no requirement to change your own application's component library in lockstep with the OneCX libraries. The v9.0.0 release is about what OneCX's own libraries are built with; how your application consumes it is your choice on your own timeline.

[#angular-23-forward-look]
== What comes next: Angular 23

The move to Optimus UI is the Angular 22 step. A further, later effort moves OneCX's own components to **Angular Material + Tailwind CSS** with **Angular 23** support. That is a separate, larger migration — see the xref:migrations/angular-23/migration-plan.adoc[Angular 23 migration guide]. Optimus UI support is retained in that effort as well, so applications relying on the PrimeNG-style API are not forced to change.
