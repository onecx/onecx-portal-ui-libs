[#integration-testing]
= Integration Testing

If a change has to be exercised inside the OneCX Shell together with one or more local applications, build the libraries locally and copy them into the `node_modules` of the shell and the applications you want to test. This guide explains how to set up that local development environment for testing changes to the libraries, located in the *onecx-portal-ui-libs* repository, and integrating them into local applications and a local xref:documentation:onecx-shell:index.adoc[OneCX Shell].

[#prerequisites]
== Prerequisites

Before proceeding, make sure you have read the following documentation:

* xref:documentation:onecx-local-env:index.adoc[OneCX Local Environment]

These resources provide essential background on setting up a local OneCX environment and running custom applications.
*This guide assumes you already know how to start OneCX locally and how to replace application images with local versions.*

[#preparing-the-library-checkout]
== Preparing the library checkout

To begin making changes and contributing to the libraries:

. Fork the repository: https://github.com/onecx/onecx-portal-ui-libs
+
**Important:** Do **not** just copy the `main` branch.
You may need to work on other branches to apply changes to other library release lines.

. Clone your fork to your local machine. The command below assumes that you named your fork `onecx-portal-ui-libs`:
+
[source, bash]
----
git clone https://github.com/<YOUR_USER_NAME>/onecx-portal-ui-libs
----

. Navigate to the cloned repository directory and install dependencies:
+
[source, bash]
----
cd onecx-portal-ui-libs && npm i
----

. Open the project in your preferred code editor (e.g., VS Code) and start making your changes.

[NOTE]
.Checkpoint
====
At this point you should have...

* a fork of the `onecx-portal-ui-libs` repository in your GitHub account.
* a local clone of said fork on your machine.
* installed all dependencies using `npm i`.
* made some changes to the codebase.
====

[#testing-the-changes-locally]
== Testing the changes locally

To test your changes, the libraries must be built and copied into the `node_modules` folders of both the shell and the app(s) you want to test in.

While it's technically possible to only copy the changes to the `node_modules` folders of the shell in certain situations, we recommend you always copy the changes to both the shell and the app(s) to avoid issues during dependency sharing.

Complete the following steps to test your changes.

[#identify-relative-paths]
=== 1. Identify relative paths

Before copying the built libraries, you first need to decide which application(s) you want to test the changes in. After deciding on the application(s), you need to determine the relative paths from the root of `onecx-portal-ui-libs` to both the application(s) and your local clone of `onecx-shell-ui`. The relative paths will be used later and might look something like this:

* For the app(s), e.g.:
+
[source]
----
../../apps/my-cool-app
----

* For your local clone of `onecx-shell-ui`, e.g.:
+
[source]
----
../onecx-shell-ui
----

[#create-the-copy-build-to-file]
=== 2. Create the `.copy-build-to` file

Create an empty file named `.copy-build-to` in the root of *onecx-portal-ui-libs*. +
This file will contain the paths to the *node_modules* folders that the build output should be copied to.

The file can contain multiple paths, one per line. Each path must be relative to the root of *onecx-portal-ui-libs* and must point to the *@onecx* folder inside the *node_modules* folder of the target project. +
For now, leave the file empty. You will add the paths in the next step.

[#add-paths-to-copy-build-to]
=== 3. Add paths to `.copy-build-to`

Use the relative paths from step 1 and follow these patterns.

**For apps (non-shell)**

Append `/node_modules/@onecx` to the app path.

Example:
[source]
----
../../apps/my-cool-app/node_modules/@onecx
----

**Note:** Do **not** add a trailing `/`.

**For the shell**

Add one line for the shell's own `node_modules` and one line for each preloader that loads the OneCX libraries you changed.

The shell's root `node_modules` holds the `@onecx/*` runtime dependencies the shell itself builds against:
+
[source]
----
../onecx-shell-ui/node_modules/@onecx
----

The shell also loads the libraries through its preloaders. There is one preloader for each supported framework and major version: each preloader is a separate sub-project that bundles the `@onecx/*` libraries for that combination and pins the `@onecx/*` version range it was built against. The current preloaders are listed in the following table:

|===
| Preloader | Framework & version

| `pre_loaders/angular-18`
| Angular 18

| `pre_loaders/angular-19`
| Angular 19

| `pre_loaders/angular-20`
| Angular 20

| `pre_loaders/angular-21`
| Angular 21

| `pre_loaders/react-19`
| React 19
|===

Append `/node_modules/@onecx` to the preloader path of every preloader that loads the libraries you changed, or that the application(s) you are testing in depend on. For example, if you are testing an Angular 19 application:
+
[source]
----
../onecx-shell-ui/pre_loaders/angular-19/node_modules/@onecx
----

**Note:** Similar to apps, do **not** add a trailing `/` to any of the paths.

[NOTE]
.Checkpoint
====
At this point, your `.copy-build-to` file should contain two or more paths (the shell root, at least one preloader, and at least one app), each on a new line, pointing to the `@onecx` folder inside the `node_modules` folder of the target projects (apps and/or shell).

The file might look something like this:

[source]
----
../../apps/my-cool-app/node_modules/@onecx
../onecx-shell-ui/pre_loaders/angular-19/node_modules/@onecx
../onecx-shell-ui/node_modules/@onecx
----
====

[#build-and-copy-the-libraries]
=== 4. Build and copy the libraries

Once you have correctly set up the `.copy-build-to` file, you are ready to build and copy the libraries to the specified paths.

Before building, make sure to remove potentially outdated cached builds by running:

[source, bash]
----
rm -rf dist .nx/cache
----

Afterwards, build and copy the libraries by running:

[source, bash]
----
npm run build-copy
----

[NOTE]
.Checkpoint
====
At this point, you should see terminal output indicating that the libraries have been built and copied to the specified paths. If you encounter any errors, refer to the error messages and ensure that the paths in the `.copy-build-to` file are correct.
====

[#prepare-the-shell-and-apps-for-local-testing]
=== 5. Prepare the shell and app(s) for local testing

Before running the shell and app(s) with the locally built libraries, you need to make some adjustments to ensure the local versions are used correctly:

. Open the `package.json` files of each app, preloader, and shell that the libraries were copied to.
. Increase the version numbers of the OneCX packages that were overwritten so the local builds are picked up.
+
TIP: Ideally, use the version number your changes will be released in. Any version number higher than the current one works. Bump the packages in each preloader you copied to and in each app you are testing in to the same version, so the shell, the preloader(s), and the app(s) all resolve the same libraries at runtime.

. **Do not** run `npm install` after changing the version numbers.
. Before running the app(s) (non-shell), delete any build caches to ensure a clean build environment.
+
[source, bash]
----
rm -rf dist .nx/cache .angular
----
. Before running the shell, delete the build caches of each preloader you updated and of the shell itself to ensure a clean build environment.
+
For example, to clear the `angular-19` preloader and the shell root:
+
[source, bash]
----
rm -rf pre_loaders/angular-19/dist pre_loaders/angular-19/.nx/cache dist .nx/cache
----
+
If you updated several preloaders, clear the `dist` and `.nx/cache` of each of them in the same way.

[NOTE]
.Checkpoint
====
At this point, you should have updated the version numbers in the `package.json` files of the shell and app(s) where the libraries were copied to. Additionally, you should have deleted any build caches to ensure a clean build environment.
====

[#run-onecx-shell-and-apps]
=== 6. Run OneCX Shell and the app(s)

After completing the previous steps, you are now ready to run OneCX Shell and the app(s) with your local library changes.

To do so, follow the documentation on xref:documentation:onecx-docs-start:first-app/running_custom_apps_overview.adoc[running custom applications locally].

TIP: The steps for running the shell should match the steps for running existing OneCX core apps.
