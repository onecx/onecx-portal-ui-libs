= Integration Contract & Topics
:idprefix:
:idseparator: -
:dev-docs-index: ../README.adoc
:shell: https://github.com/onecx/onecx-shell-ui/blob/main

Apps, Remote Components and the Shell talk at runtime by exchanging *Topics*, not by calling each other's code. Every other Area builds on this messaging contract, so it is Area 1 of the link:{dev-docs-index}[Dev Docs]. This Area covers the mechanism only; the meaning of each concrete Topic (workspace, theme, permissions, …) belongs to its owning Area.

== Problem

A OneCX page hosts one Shell, the currently routed App and any Remote Components it hosts. These units are released separately, use Angular or React, share no object graph or DI container, and may load at different times.

They must still stay in sync: the Shell owns the workspace, theme, route and user profile, and Apps and Remote Components react to them. The Topic contract is their only channel, so every other Dev Docs mechanism depends on it.

== Big picture

The libraries in this repository define the vocabulary and machinery; the Shell and Apps use them:

* *Libraries* (`@onecx/accelerator`, `@onecx/integration-interface` and the Angular/React adapters) provide the `Topic` and `Gatherer` primitives, the concrete shared and request/response (RPC) Topics, and the per-framework services and contexts that wrap them.
* *Shell* advertises its capabilities, publishes shared state and answers requests for Shell-owned data.
* *Apps / Remote Components* subscribe to the state they need. Where needed, they also publish Topics or answer Topic requests, including between Apps.

[source,mermaid]
----
sequenceDiagram
  participant Shell
  participant App
  participant Remote as Remote Component

  Shell->>Shell: publish workspace / theme / user
  App->>App: subscribe to shared Topics
  Remote->>App: TopicGet (late subscriber asks for current state)
  App-->>Remote: TopicNext (current value)
  App->>Shell: RPC request (e.g. permissions)
  Shell-->>App: RPC response
----

== Debugging conventions

All Topics log under `@onecx/accelerator:Topic:<name>` and all Gatherers under `@onecx/accelerator:Gatherer:<name>`. Set `localStorage.debug` and reload the page:

* `localStorage.debug = '@onecx/accelerator:Topic:*'` (or `:Gatherer:*`): every Topic or Gatherer.
* `localStorage.debug = '@onecx/accelerator:Topic:<name>'` (or `:Gatherer:<name>`): one concrete instance.
* `localStorage.debug = '@onecx/accelerator:Topic:*:error'`: errors only.

Each Unit's *Debugging* section adds only what is specific to it. For general cross-App tracing, see link:../diagnostics/tracing-communication.adoc[Area 13], also listed under each Unit's Related Units.
