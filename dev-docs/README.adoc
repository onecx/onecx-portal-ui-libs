The Dev Docs explain how OneCX works at runtime, one concept at a time. Each page covers both sides of a mechanism: what the libraries in this repository provide, and how the https://github.com/onecx/onecx-shell-ui[OneCX Shell] uses it.

toc::[]

== Who these pages are for

* Maintainers of the OneCX libraries and the Shell.
* Advanced App developers who need to understand a mechanism in depth.

The Dev Docs explain how things work and why. Other documentation covers the following:

* Step-by-step usage guides are in https://github.com/onecx/docs-guides-ui[docs-guides-ui].
* Library API and component documentation is in the libs Antora docs (`docs/`) and Storybook.

== How the Dev Docs are organised

Area:: A large subject, for example Styling & Style Isolation. Each Area has its own folder. The folder's `README.adoc` is the Area overview page. It describes the problem, gives the big picture across libs and Shell, and lists the Units in reading order.
Unit:: One small page that answers one question. A Unit takes about 10 minutes to read and follows the link:{unit-template}[Unit template].

All pages are written from the current `main` branch of this repository and of the Shell. The rules for writing them are defined once, in the link:{unit-template}[Unit template].

== Areas and Units

Read the Areas in the order below. Area 1 defines the integration contract that all other Areas build on.

Each Area is listed with its folder (`dev-docs/<area-slug>/`) and its planned Units with their page files. The paths are fixed so that pages can link to each other before the target page is written. Links are added here when a page exists. Unplanned pages must not reuse these paths.
