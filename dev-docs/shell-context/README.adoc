This Area explains the data the Shell provides to Apps and where that data comes from: what "context" the Shell puts into the page, when it becomes ready for Apps to read, and how the Workspace configuration is loaded and distributed to the Topics and services that every App depends on.

toc::[]

== Problem

An App does not know which Workspace (portal) it is running in, which routes and endpoints exist, which configuration keys apply, or which parameters the Shell wants it to honour. None of this is compiled into the App. The Shell owns the answer to all of it and has to hand it over at runtime, through the Topic contract of Area 1 (Integration Contract & Topics). This Area covers two things that every other Area builds on:

* *readiness* — which Topics hold the Shell's context, and how an App can tell when a given piece of context has actually arrived; and
* *distribution* — how the Workspace configuration is loaded on the Shell side and fanned out to the `current-workspace`, `configuration` and `parameters` Topics and the services that read them.

The libraries only *carry* this data; they do not produce it. The Shell is the single producer.

== Big picture

The Shell is the only source of Shell context. It loads its runtime configuration and the Workspace configuration during bootstrap, then publishes the results onto Topics. Apps (Angular or React) get the same Topics through the libs, which wrap them in services or hooks. The split of work is shown below.

[source,mermaid]
----
flowchart LR
  subgraph Shell
    ENV[env.json / APP_CONFIG]
    WS[Workspace config BFF]
    P[Parameters service]
    CfgInit[configurationServiceInitializer]
    WsInit[workspaceConfigInitializer]
  end
  subgraph Topics
    CFG[configuration]
    WS_T[current-workspace]
    PAR[parameters]
    MFE[current-mfe]
  end
  subgraph App
    S1[ConfigurationService]
    S2[AppStateService / WorkspaceService]
    S3[ParametersService / useParameters]
  end
  ENV --> CfgInit --> CFG
  WS --> WsInit --> WS_T
  WS --> WsInit --> PAR
  WsInit --> MFE
  CFG --> S1
  WS_T --> S2
  WS_T --> S3
  MFE --> S3
----

The same Topics exist in both repositories. The Shell *publishes* them; an App *subscribes* to them. An App never writes Shell context itself — reading a Topic before the Shell has published it is the main failure mode this Area documents.
