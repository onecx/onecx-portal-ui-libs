This page is the overview of the **Theming & Visual Assets** Area of the Dev Docs. It explains the problem the Area is about, how the work is split between the OneCX libraries in this repository and the {shell_repo}[OneCX Shell], and lists the Units that belong to the Area in reading order. It does not explain any single mechanism in depth — that is the job of the individual Unit pages, which follow the Unit template.

[#problem]
== Problem

A *theme* in OneCX is the suite of values — colours, fonts, favicon and logo — that makes the same pages look different per Workspace. The mechanism is split across two repositories and is only fully understood by reading both halves:

* the **libraries** in this repository define the shared data structure (`Theme`), the channel that carries it (`CurrentThemeTopic`) and, for each framework, the code that turns theme values into usable CSS variables and component-library design tokens;
* the **{shell_repo}[Shell]** reads the active Workspace's theme and puts the values on the page (theme variables on the root element, favicon and logo), so that every application loaded on the page can react to the same theme at runtime.

None of this lived in a single place before: the mechanism was documented only in short, partly outdated pages and only partially in code comments. This Area gives each half of the flow one page, grounded in the current `main` code of both repositories.

[#big-picture]
== Big picture

One theme value travels from the backend to the rendered page in two stages. The same `Theme` object drives both, so a reader who understands both Units can trace a single colour from the Workspace all the way to a component.

[source,mermaid]
----
flowchart LR
  subgraph Backend
    T[Workspace theme]
  end
  subgraph Shell
    S1[theme CSS variables on root]
    S2[favicon & logo]
  end
  subgraph "Libs (this repo)"
    C1[CurrentThemeTopic / Theme]
    C2[Angular: ThemeConfigService -> PrimeNG preset]
    C3[React: StyleRegistry -> CSS variables + tokens]
  end
  T -->|CurrentThemeTopic| C1
  T --> S1
  T --> S2
  C1 --> C2
  C1 --> C3
  S1 -->|values read by apps| C2
  S1 -->|values read by apps| C3
----

* **Theme → page** is the first stage: the Shell puts the theme's CSS variables, favicon and logo on the page and the libraries expose the current theme through the `CurrentThemeTopic`. See link:{theme_to_page}[Theme → page].
* **Theme → PrimeNG/PrimeReact tokens** is the second stage: each framework maps the theme values onto the design tokens of the component library, so PrimeNG/PrimeReact components pick up the Workspace theme. See link:{theme_to_tokens}[Theme → PrimeNG/PrimeReact tokens].
