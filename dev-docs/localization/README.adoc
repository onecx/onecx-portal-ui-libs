= Localization
:idprefix:
:idseparator: -

Localization is the Area that answers a single, shared question: **which user is signed in, in which language, and where do the words on screen come from.** The mechanism is split across the libraries in this repository and the https://github.com/onecx/onecx-shell-ui[OneCX Shell], and it is consumed by both Angular (ngx-translate) and React (i18next) on the same page.

== Problem

A OneCX page is a module-federation composition: several Apps and Remote Components, built with different frameworks, share one browser window. That creates two constraints that a plain i18n setup cannot meet:

* There is exactly **one signed-in user** and **one active language**, but many frameworks that must all stay in step with that decision.
* Each App and Remote Component ships **its own translation files** at its own base URL, shared libraries ship their own, and all of them must be merged without key collisions: while the *same* file is never fetched more than once, even when several Apps need it.

This Area documents how both problems are solved. It does not describe how to *configure* a translation for your App (that belongs in https://github.com/onecx/docs-guides-ui[docs-guides-ui]); it explains the runtime mechanism and why it is shaped the way it is.

== Big picture

The work is divided along the same libs / Shell boundary that the rest of the Dev Docs use. The Shell owns the *input* (the signed-in user and the profile it fetched); the libraries own the *decision* and the *distribution*.

Four Units in this Area describe the core mechanism in depth:

* **Profile load & language decision**: the profile Topic and the pure function that turns a profile into the one language every framework must use.
* **App translations load & sharing**: how per-App and per-library translation files are resolved, deep-merged, and shared page-wide through a global cache.
* **Remote Component translations**: how a Remote Component adds its own translation files, at its own base URL, to the shared loader chain and cache.
* **Missing-translation fallback**: the locale walk and the static → dynamic → raw-key fallback when a key cannot be found.

Three further Units cover the surrounding mechanisms: link:./locale-and-timezone-formatting.adoc[locale & timezone formatting], the link:./react-translations.adoc[React pipeline], and link:./dynamic-translations.adoc[dynamic translations].
